# CALIBRA — Security & Regulatory Audit Integrity

## 1. Regulatory Audit Integrity
In legal metrology, compliance certificates must be protected against post-issuance tampering or retroactive modification.

### 1.1 Cryptographic SHA-256 Checksumming
Every standardized OIML R76-2 report generated by CALIBRA is hashed using SHA-256 upon PDF creation. The checksum is:
1. Imprinted in the footer of the physical PDF.
2. Stored in the database `reports` table.
3. Automatically verified via `GET /reports/{id}/verify`.

If any byte in the PDF is altered post-issuance, the verification endpoint immediately flags the document as **`TAMPERED_OR_MODIFIED`**.

### 1.2 Immutability & Revisions
Finalized reports cannot be overwritten. If new observations or tests are executed, a new revision (`REV2`, `REV3`) is created with its own unique cryptographic hash and audit trail record.

## 2. Role-Based Access Control (RBAC)

CALIBRA models four regulatory personas:
1. **Technician:** Authorized to input raw observations, record turning point weights $\Delta L$, and run preliminary calculations.
2. **Reviewer / Metrologist:** Authorized to review evidence chains, evaluate CoverageGate checklists, and approve official reports.
3. **Administrator:** Authorized to register laboratory standard weights, configure reference locations, and update ruleset editions.
4. **Auditor:** Read-only access to historical compliance replays, cryptographic audit logs, and ruleset version comparisons.
